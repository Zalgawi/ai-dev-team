# Trail 100 Project Rules

## Source of truth

The Trail 100 peak list is based on the published
Live for the Outdoors Trail 100 challenge list.

Do not invent additional Trail 100 peaks.

## Data

Peak data should be stored separately from UI components.

Do not hard-code the peak list throughout the application.

Refer to the list of 100 in trail-100-list.txt (https://www.livefortheoutdoors.com/trail-100/)

## User data

Completion status must be separate from the canonical
Trail 100 peak dataset.

## Architecture

Prefer simple, maintainable solutions.

Avoid unnecessary dependencies.

## UI

The application should feel appropriate for:

- hiking
- mountains
- outdoors
- exploration

The design should prioritise clarity and usability.

## Testing

Core user flows must have automated tests.

Responsive behaviour must be tested.
